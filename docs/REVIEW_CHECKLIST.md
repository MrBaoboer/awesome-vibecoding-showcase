# 项目审核清单

本文件供维护者审核新项目和复核现有条目。提交者无需填写本清单，也无需确定最终分类。

## 审核记录

- 项目名称：
- 提交 Issue：
- 审核日期：
- 审核者及利益关系：

## 范围

- [ ] 是可运行的软件产品，不是开发工具、IDE、编辑器、插件、模型、组件、模板、教程或资源清单。

任一项不通过，停止审核并说明原因。

## C1–C5

- [ ] **C1｜公开体验：** 体验或演示可公开访问；已实际验证一个核心流程，并记录限制和日期（D5）。
- [ ] **C2｜公开源码：** 源码无需特殊授权即可查看，包含产品主体实现，并与体验产品相符（D3 / D5）。
- [ ] **C3｜AI 实质性参与：** 已核对工具、参与深度、自然语言协作方式和公开过程证据；AI 的参与不只限于文档、测试、少量修复或素材生成（D4）。
- [ ] **C4｜完成度、实用性或创新性：** 核心流程可运行，且有具体质量依据，不以 Star 或宣传声量代替证据（D1 / D2）。
- [ ] **C5｜真实与可验证：** 产品、源码、归属、时间线和证据一致；利益关系已披露；重要事实有公开来源。

任一项不通过，不得收录。

## D1–D5

- [ ] **D1：** 目标用户、场景和问题明确。
- [ ] **D2：** 2–4 项已上线核心功能及实际价值完整。
- [ ] **D3：** 3–8 项主要技术准确，并与源码相符。
- [ ] **D4：** AI 工具、参与深度、协作方式和证据完整。
- [ ] **D5：** 在线体验和源码地址均为公开直接地址。

任一字段缺失，使用 `status: needs-info`，一次性列出需要补充的内容。

## 分类与重复

- [ ] 维护者已按[分类规则](CATEGORIES.md)选择一个有效的一级和二级分类。
- [ ] 现有条目、开放 Issue 和 Pull Request 中没有同一项目。
- [ ] 边界分类的理由已记录在审核 Issue。

## 结果

- `status: approved`：C1–C5 全部通过，D1–D5 完整，分类有效。
- `status: needs-info`：没有明确反证，但仍缺少可补充的信息。
- `status: declined`：任一强制条件不满足或无法公开核验。
- `status: removed`：已收录项目不再满足任一 C 条件。

项目数据合并前使用 `status: approved`；合并后改为 `status: listed`。
