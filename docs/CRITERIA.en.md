# Inclusion Criteria

[Chinese version](CRITERIA.md)

Only runnable software products are eligible. AI coding tools, IDEs, editors, plugins, models, component libraries, frameworks, templates, tutorials, prompt collections, and concept-only projects are out of scope.

A project must pass every criterion from C1 through C5 and provide every field from D1 through D5. Stars, funding, author reputation, and promotional reach do not affect the decision.

## C1–C5 | Eligibility

| ID | Pass condition | Main verification |
| --- | --- | --- |
| C1 — Public experience | A publicly accessible product, demo, or online experience lets a reviewer verify at least one core flow | Open the experience and record the date, tested flow, and any account, region, or device limits |
| C2 — Public source | A source repository is viewable without special access and contains the primary implementation of the public product | Open the repository and compare the product name, main features, build structure, and deployed version |
| C3 — Substantial AI involvement | AI generated and iterated most core feature code through conversation, or natural-language instructions drove the primary implementation | Verify the tools, depth, typical workflow, and at least one public piece of process evidence |
| C4 — Completeness, utility, or innovation | The core flow works and the product is more than a shell or concept; specific evidence shows completeness, utility, or innovation | Run the core flow, compare claims with shipped features, and record reproducible quality evidence |
| C5 — Authentic and verifiable | The product, source, author statements, and evidence are consistent, and material claims can be checked from public sources | Cross-check names, features, ownership, timeline, access limits, and disclosed relationships |

C3 does not include AI used only for documentation, comments, tests, a small number of bug fixes, local completion, or asset generation. Runtime use of an AI model does not by itself show that AI implemented the product. Do not infer AI involvement from code style.

Screenshots, videos, and landing pages alone do not pass C1. A repository containing only documentation, compiled artifacts, or unrelated code does not pass C2. A nonfunctional concept does not pass C4. Material claims that depend on private files, private groups, or untraceable screenshots do not pass C5.

## D1–D5 | Listing Content

| ID | Required content | Requirement |
| --- | --- | --- |
| D1 | Problem | Identify the target user, context, and specific problem |
| D2 | Core features and practical value | Describe 2–4 shipped features and what each does for users |
| D3 | Main technology stack | List 3–8 technologies that make up the primary product |
| D4 | AI's development role | State the tools, depth, typical workflow, and public evidence |
| D5 | Public links | Provide direct links to both the live experience and source repository |

## Review Outcomes

- **Accept:** C1–C5 all pass and D1–D5 are complete.
- **More information needed:** No requirement clearly fails, but a public evidence item or listing field can reasonably be added.
- **Decline:** Any C criterion fails, conflicts cannot be resolved, public verification is impossible, or the project is out of scope.

Evidence must not contain secrets, tokens, passwords, private-repository content, personal data, or material the submitter has no right to publish. Redacted evidence must retain enough context to connect it to the core development process.
