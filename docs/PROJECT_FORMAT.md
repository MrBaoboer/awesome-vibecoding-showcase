# 单项目展示格式

所有条目使用同一结构，便于读者横向比较、贡献者更新和自动化检查。展示字段 D1–D5 必须完整；资格证据 C1–C5 在审核记录中留存，必要时在条目中给出直接链接。

## 格式规则

1. **名称：** 使用产品公开名称，不添加“最佳”“第一”等无法核验的修饰。
2. **问题（D1）：** 1–2 句，明确目标用户、场景和具体问题。
3. **功能与价值（D2）：** 2–4 项，只写已上线功能；每项同时说明给用户带来的价值。
4. **技术栈（D3）：** 列出 3–8 个构成主体的主要技术，不粘贴完整依赖清单。
5. **AI 角色（C3 / D4）：** 必须包含 AI 工具、参与深度、典型自然语言协作方式和公开证据。
6. **链接（C1 / C2 / D5）：** 分别提供在线体验和公开源码的直接 HTTP(S) URL，优先 HTTPS；若只能使用 HTTP，须在核验说明中记录安全限制。不得使用搜索结果页或不透明短链。
7. **质量与核验（C4 / C5）：** 用一句话说明已验证的核心流程与质量依据；不可确认的事实写“未核实”。
8. **分类：** 使用一个一级分类和其下一个二级分类 slug。
9. **日期：** 记录首次收录日期；事实、链接或证据更新不改变首次收录日期。
10. **语言：** 中文为主；字段名和关键参与信息提供英文可理解的固定标识。项目名、URL 和分类 slug 不翻译。

## 示例，非真实收录

> **注意：以下产品、描述和证据均为虚构示例，链接故意使用保留示例域名，不能作为真实候选或收录依据。**

### FocusFlow Garden — 示例，非真实收录

> **解决的问题 / Problem（D1）：** 帮助经常被多项短任务打断的自由职业者，把一天的工作拆成可完成的专注时段并回顾实际用时。

- **核心功能与价值 / Features & value（C4 / D2）：**
  - 将任务拖入专注时间线：让用户在开始工作前看见实际容量，减少过度排期。
  - 完成专注时段后生成本地周回顾：帮助用户比较计划与实际用时。
- **主要技术栈 / Tech stack（D3）：** TypeScript、React、IndexedDB、Vite。
- **AI 开发角色 / AI role（C3 / D4）：**
  - **工具 / Tools：** 示例 AI 编程助手。
  - **参与深度 / Depth：** 通过自然语言迭代实现了时间线交互、本地数据模型和周回顾计算的主体代码。
  - **典型协作 / Workflow：** 人类先描述使用场景和验收行为，AI 生成端到端实现；随后根据浏览器测试结果多轮修正状态同步与边界情况。
  - **公开证据 / Evidence：** [虚构证据地址，仅示例](https://example.com/focusflow/evidence)。
- **在线体验 / Try it（C1 / D5）：** [虚构体验地址，仅示例](https://example.com/focusflow/demo)。
- **公开源码 / Source（C2 / D5）：** [虚构源码地址，仅示例](https://example.com/focusflow/source)。
- **质量与核验 / Quality & verification（C4 / C5）：** 示例声称“创建任务—完成专注时段—查看周回顾”流程可运行；由于本条为虚构示例，不构成真实核验。
- **分类 / Category：** `productivity-collaboration / personal-productivity`
- **首次收录 / Added：** `2099-01-01（虚构日期）`

## 不合格展示写法

- “一个革命性的 AI 平台”——没有 D1 的目标用户、场景与问题。
- “功能很多，未来会加入更多能力”——没有 D2 的已上线功能与价值。
- “AI + Web3 + Cloud”——不能替代 D3 的具体主体技术。
- “100% 用 AI 做的”——缺少 C3 / D4 的工具、深度、协作方式与证据。
- 只提供体验或源码其中一个地址——D5 不完整，同时不满足 C1 或 C2。
- 把 Star、融资或作者知名度当作 C4/C5 的唯一证据。
